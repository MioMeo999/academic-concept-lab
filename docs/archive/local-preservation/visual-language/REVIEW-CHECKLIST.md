# Academic Concept Lab — Visual Review Checklist

Use this after every visual iteration.

## Identity
- [ ] The accepted Home Hero is preserved as the visual benchmark
- [ ] Home, Gestalt and JD–R are used as role-specific benchmarks, not copied templates
- [ ] RTA is treated as a method-specific benchmark for reflexive/revisable knowledge, not a template
- [ ] The page shares visual DNA with the benchmarks while its geometry comes from the theory
- [ ] Each section has a chosen art intensity and at most one dominant art gesture
- [ ] Rich and quiet sections alternate; artwork is omitted when it adds no clarity
- [ ] Feels like Academic Concept Lab rather than a generic academic website
- [ ] Contemporary rather than nostalgic
- [ ] White canvas remains visually important
- [ ] Precise underneath, human on top

## Typography
- [ ] Formal scholarship remains clearly typeset
- [ ] Handwriting is selective
- [ ] Typography feels editorial and serious
- [ ] Body text is comfortably readable

## Drawing
- [ ] Drawing is doing intellectual work
- [ ] It is integrated with the page rather than pasted beside it
- [ ] It avoids clean-vector illustration as the default
- [ ] There is enough material variation

## Pigment
- [ ] Colour behaves like material rather than UI accent
- [ ] Layering, pressure, overlap or accumulation are visible where appropriate
- [ ] Colour is controlled rather than everywhere
- [ ] Quiet sections genuinely become quieter

## Theory-specific composition
- [ ] Composition plausibly belongs to this theory
- [ ] No universal hero/cards/diagram template
- [ ] Theory structure affects spatial behaviour

## Discovery and Library surfaces
- [ ] Can the reader find the next useful record quickly?
- [ ] Does active search or filtering remove unnecessary discovery material?
- [ ] Does selected-field browsing preserve meaningful field structure?
- [ ] Is information density appropriate to the reader's current intention?
- [ ] Would the presentation still work with substantially more records?
- [ ] Are records easy to scan without becoming generic database rows?
- [ ] Is visual material helping discovery rather than competing with it?

### Personal return surfaces
- [ ] Does the personal collection feel simpler than the discovery surface it came from?
- [ ] Can a saved record be recognised and reopened immediately?
- [ ] Does the page work intentionally at zero, one and multiple items?
- [ ] Is grouping present only when it materially helps recognition?
- [ ] Does interface language match the actual persistence model, without invented recency?
- [ ] Is return more prominent than collection management?
- [ ] Does removing the final item produce a coherent, accessible empty state?

## Interactive Editorial Drawing
- [ ] The live HTML keeps claims, qualifications, evidence, limitations,
  sources and provenance selectable, searchable and semantically structured
- [ ] The interaction has a theory-specific reason to exist
- [ ] What stays constant and what changes are explicit
- [ ] The stable reference remains visible during comparison or context change
- [ ] Focus does not imply disappearance when states coexist
- [ ] Residual states remain perceptible where the theory requires them
- [ ] The drawing field, annotations or relationships respond meaningfully to
  state changes
- [ ] The interaction transforms a relationship rather than only swapping an
  image or toggling visibility
- [ ] If the same authored artwork appears more than once, each use has a
  different conceptual role
- [ ] Reuse feels like revisiting one world rather than repeating one image
- [ ] A crop, fragment or live overlay replaces unnecessary full-image
  repetition where appropriate
- [ ] Essential meaning remains live, accessible HTML rather than raster text
- [ ] Controls are semantic, discoverable, keyboard accessible, visibly
  focused, touch-usable and screen-reader legible
- [ ] State is understandable without colour alone
- [ ] Motion explains a conceptual change and `prefers-reduced-motion` remains
  fully functional
- [ ] The page does not flatten a useful existing interactive experience into
  static artwork

## Annotation
- [ ] Every handwritten note has a reason to exist
- [ ] Notes reveal assumptions, boundaries, questions or relationships
- [ ] Avoids filler such as “important” or “remember this”

## Quiet scholarship
- [ ] Evidence remains rigorous and inspectable
- [ ] Scope and Limitations are visible without generic cards
- [ ] Provenance is understandable
- [ ] Sources and References remain easy to use
- [ ] Quiet sections still feel like Concept Lab

## Material authenticity
- [ ] Pencil looks varied rather than procedurally repetitive
- [ ] Hatching, smudging, erasure, overlap, contour and ghost marks are selective
- [ ] Page avoids an all-hatching or all-SVG-engine look
- [ ] Result feels artistic enough

## Anti-patterns
- [ ] Not SaaS
- [ ] Not dashboard
- [ ] Not generic editorial portfolio
- [ ] Not card-grid website
- [ ] Not scrapbook
- [ ] Not sticky-note theme
- [ ] Not beige notebook
- [ ] Not children’s educational graphics
- [ ] Not decorative doodle layer
- [ ] Not repeated left-copy/right-image layout

## Final questions

> **If someone saw this page without the logo, would they recognise that it belongs to the same visual world as the best Academic Concept Lab references?**

> **Does this feel like a page for thinking with theory, rather than a page that merely explains theory?**

> **Could this interaction only make sense for this theory, and does it make the relationship easier to perceive?**

> **Is the artwork participating as material, field, fragment or trace, rather than being treated as the finished interface?**

## Art / code balance

- [ ] Is a complex expressive image being forced into procedural SVG unnecessarily?
- [ ] Would a generated/authored art asset carry the intended material quality better?
- [ ] Where authored art is the approved layer, is it preserved as the primary asset rather than redrawn in SVG/CSS?
- [ ] Is code being used mainly where structure, behaviour, responsiveness, or interaction requires it?
- [ ] Does the final page avoid looking like a technical diagram system merely because it was coded?
